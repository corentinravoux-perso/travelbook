# 0001. Export fidelity: vector or raster print PDF

Status: spike result, awaiting the gate (Corentin). Date: 2026-11-14. Task 7.3 implements the route chosen here.

## Context

Design §10 offers a vector print PDF (Chromium `printToPDF`) if it keeps photo resolution and fonts, and falls back to
600 dpi page captures assembled with pdf-lib otherwise. The spike (`spikes/export-fidelity/`) renders one page of
216 x 303 mm (A4 + 3 mm bleed) in a hidden Electron 45.3.2 window (Chromium of that release, Linux, Wayland session,
software-composited, `--no-sandbox`). The page holds: a gradient background; a 2551 x 1700 JPEG in a rounded frame with box shadow;
a 1800 x 1800 JPEG in an ellipse clip with `filter: saturate(1.3) contrast(1.1)`; a 1600 x 1200 JPEG at `opacity .8`,
rotated 7 degrees; an SVG sticker and a 600 x 600 PNG sticker with alpha, both rotated; two text blocks in two woff2
fonts (Playfair Display 700, Caveat 700; one with `text-shadow`). Photos are synthetic (gradients, fine detail, noise;
JPEG q92), generated by `gen-assets.mjs`; no personal photo. Poppler 'pdfimages / pdffonts / pdfinfo / pdftoppm' did the checks.

## Measurements

Commands run from `spikes/export-fidelity/`; PDF flags noted per measurement.

### 1. Page size (`python3 mm.py out/*.pdf`, built on `pdfinfo -box`)

Target 216 x 303 mm = 612.283 x 858.898 pt.

| `printToPDF` options                                           | Result (pt)                                                                 | mm                | delta (mm)          |
| -------------------------------------------------------------- | --------------------------------------------------------------------------- | ----------------- | ------------------- |
| only CSS `@page` (Electron default, `preferCSSPageSize` false) | 612 x 792                                                                   | 215.900 x 279.400 | CSS ignored, Letter |
| `preferCSSPageSize: true`                                      | 612 x 858.96                                                                | 215.900 x 303.022 | -0.100 / +0.022     |
| `pageSize: {width: 216/25.4, height: 303/25.4}` (inches)       | 612.96 x 858.96                                                             | 216.239 x 303.022 | +0.239 / +0.022     |
| `pageSize` in microns (216000 x 303000)                        | no PDF: `Failed to generate PDF: Printing failed` (printToPDF takes inches) | -                 | -                   |

Chromium quantises page sizes (other widths tried: 210 mm gives 209.889, 217 gives 217.001, 218 gives 218.017, 230 gives 230.039).
Verdict: `preferCSSPageSize: true` is the only usable mode. Height is exact; width is short by exactly 0.100 mm,
on the 0.1 mm tolerance (holds at equality, no margin). The MediaBox can be rewritten with pdf-lib in Task 7.3 (TrimBox and
BleedBox are set there anyway).

### 2. Image pixel sizes and encoding (`pdfimages -list out/out-prefer-css.pdf`)

| Photo                            | Source                   | In PDF                      | Encoding                                | Size in PDF            |
| -------------------------------- | ------------------------ | --------------------------- | --------------------------------------- | ---------------------- |
| frame (rounded corners + shadow) | 2551 x 1700, 1,867,543 B | 2551 x 1700                 | `jpeg`, passthrough (not re-encoded)    | 1824K (= source)       |
| opacity .8 + rotate 7 degrees    | 1600 x 1200, 843,614 B   | 1600 x 1200                 | `jpeg`, passthrough                     | 824K (= source)        |
| ellipse clip + `filter`          | 1800 x 1800, 1,403,955 B | **948 x 797**               | **`image` (Flate, lossless re-encode)** | **2116K + 2.2K smask** |
| PNG sticker (alpha, rotated)     | 600 x 600                | 600 x 600 + 600 x 600 smask | Flate (lossless)                        | 78K + 30K              |
| SVG sticker                      | -                        | no image object: vector     | -                                       | -                      |

Extra raster objects Chromium creates, not photos: box-shadow mask 2469 x 1713 gray JPEG (300 dpi, 35K); text-shadow mask
1177 x 158 gray JPEG (300 dpi, 8K).
The filtered photo is the only failure: 948 x 797 instead of 1800 x 1800, and 2.1 MB lossless instead of a JPEG passthrough.
The 948 x 797 size is the bounding box of the clipped ellipse at 300 dpi.

### 3. Fonts (`pdffonts out/out-prefer-css.pdf`)

`PlayfairDisplay-Bold` and `Caveat-Bold`: both `CID TrueType`, `emb yes`, `sub yes`, `uni yes`. Text is vector. Holds.

### 4. Effects, each alone (`... run.mjs --prefer-css --variants`, `out/var-*.pdf`; one photo, one effect, `pdfimages -list`)

| Effect alone                                    | Photo in PDF                                    | Result                                                                                 |
| ----------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------- |
| plain (no effect)                               | 2551 x 1700 jpeg                                | passthrough                                                                            |
| `border-radius` + `overflow: hidden`            | 2551 x 1700 jpeg                                | passthrough                                                                            |
| `box-shadow`                                    | 2551 x 1700 jpeg + 2469 x 1713 gray shadow mask | passthrough, shadow is a separate 300 dpi mask                                         |
| `clip-path: ellipse()`                          | 1800 x 1800 jpeg                                | passthrough                                                                            |
| `filter: saturate(1.3) contrast(1.1)` (no clip) | **950 x 950 rgb Flate** (+ smask)               | **photo rasterised at 300 dpi of its 80 mm frame, 1800 px source downsampled, 2.5 MB** |
| `opacity: .8`                                   | 1600 x 1200 jpeg                                | passthrough                                                                            |
| `transform: rotate(7deg)`                       | 1600 x 1200 jpeg                                | passthrough                                                                            |
| `text-shadow`                                   | text vector + 1177 x 158 gray mask              | text unaffected                                                                        |
| PNG sticker, SVG sticker (rotated)              | 600 x 600 Flate + smask; SVG vector             | fine                                                                                   |

Only `filter` rasterises, and it rasterises that photo alone. No effect rasterised the whole page.

### 5. Captures (`run.mjs --prefer-css --dpi=300|600`, `Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot` with `clip.scale`, offscreen window)

| dpi | Output (px) | Time                                | Peak memory                                                                                                                                                 |
| --- | ----------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 300 | 2551 x 3579 | 1.7 s capture (2.8 s whole process) | `/usr/bin/time -v` max RSS of the Electron main process 384 MB; `app.getAppMetrics` peak working set: Browser 384 MB, GPU 260 MB, Tab 231 MB, Utility 90 MB |
| 600 | 5102 x 7157 | 6.6 s capture (7.8 s whole process) | max RSS 941 MB; Browser 941 MB, GPU 802 MB, Tab 359 MB, Utility 88 MB (sum of peaks about 2.2 GB)                                                           |

Both succeed with the exact sizes required. A plain hidden window does not paint: `captureScreenshot` hangs, so captures need
`offscreen: true` (and `printToPDF` hangs offscreen, so the PDF needs a separate plain hidden window).

### 6. PDF versus capture (`node compare.mjs out/out-prefer-css.pdf out/out-300.png 300`; sharp, both resampled to the capture size)

`pdftoppm -r 300` gives 2550 x 3579 (page is 215.9 mm wide), capture 2551 x 3579. Mean absolute pixel difference
**4.686 / 255 = 1.838 %** at 300 dpi; at 600 dpi (`pdftoppm -r 600` 5100 x 7158 vs 5102 x 7157) 3.233 / 255 = 1.268 %.
The residual includes the 1 px width mismatch and the 300 dpi shadow masks. Visually equivalent; not pixel exact.

## Decision

Rule (task brief): vector PDF route if measurements 1 to 4 hold; otherwise raster PDF route (600 dpi captures assembled with pdf-lib).

- 1 holds only at the tolerance edge (-0.100 mm width with `preferCSSPageSize: true`).
- 2 fails for the filtered photo (948 x 797, Flate, instead of 1800 x 1800 JPEG).
- 3 holds. 4 fails for one effect: CSS `filter`.

**Decision: raster PDF route** (600 dpi page captures assembled with pdf-lib; captures work: 5102 x 7157 in 6.6 s, about 2.2 GB peak across processes).

Effects that forced it: CSS `filter` (here `saturate()` + `contrast()`) on a photo. Nothing else did: clip-path, border-radius,
box-shadow, text-shadow, opacity, rotation, SVG and alpha PNG all kept photos as JPEG passthrough at source size.

### Recorded alternative (adjustments fail only: bake them into the derivative)

Only adjustments failed. The alternative the gate may prefer: keep the vector route and apply photo adjustments
(saturation, contrast, others) in the main-process `sharp` derivative (design §10 already produces a cropped, resized derivative per
photo), so export markup never uses CSS `filter`. The spike already shows the remaining page (clip, shadow, opacity, rotation, stickers,
embedded vector text) exports as vector with JPEG passthrough (`var-clip.pdf`: the 1800 x 1800 photo without `filter` is passed through).
Caveats if chosen: the baked adjustment must match the editor preview (`SpreadView quality="export"` must not apply the CSS
filter to the same photo), the page-size width must be fixed up with pdf-lib (-0.100 mm), shadows stay 300 dpi masks, and
this alternative has not been tested with a pdf-lib MediaBox rewrite or a baked derivative of the filtered photo.
